# Автотесты двусторонней шкалы и автоскрытия

## Сквозные пользовательские сценарии — API18

Запуск на отдельном одноразовом эмуляторе API18/mdpi с именем `VolumeIcons_API18`:

```powershell
./source/tests/run-user-flows-android.ps1 -BuildOnly
./source/tests/run-user-flows-android.ps1 -Serial emulator-5600
```

По умолчанию устанавливается `output/VolumeControl-2.7.1-redesign20-verified.apk`; другой кандидат задаётся параметром `-Apk`. Runtime-команда проверяет имя AVD, API18, mdpi и признак эмулятора, затем выполняет реальные нажатия и перезагрузку. Она меняет значок и временно меняет настройки/громкость; тесты восстанавливают выбранные значения, а переключение значка возвращает вариант №7. Поэтому запуск предназначен только для выделенного одноразового AVD, не для телефона или магнитолы. Логи записываются в `output`, снимки UI — во временные файлы эмулятора.

Набор проверяет запуск/закрытие и повторный запуск; все четыре иконки; изменение и восстановление вида шкалы; короткое и подтверждённое касание с защитой и без неё с проверкой `STREAM_MUSIC`; включение автоскрытия, фактическое исчезновение, выключение и проверку видимой шкалы после ожидания; открытие микшера, изменение и восстановление уровня музыки, закрытие окна; автозапуск через включение настройки, реальную перезагрузку эмулятора, проверку запущенного сервиса и возврат прежней настройки.

`-BuildOnly` только компилирует и упаковывает UI-тесты. Полный runtime-прогон в этой среде заблокирован: ADB не смог запустить сервер (`could not read ok from ADB Server`). Поэтому наличие собранных тестов не является результатом их выполнения.

## Сменные иконки — redesign20

`run.ps1` включает модель переключения и проверку графики. Для APK redesign19 дополнительно проверяется конечный манифест, 24 изображения по плотностям, четыре крупных изображения 512×512 nodpi, ссылки application/alias на крупную графику и DEX-интеграция. Старый APK18 намеренно не проходит новую проверку: в нём лаунчер получает маленькие density-ресурсы.

```powershell
./source/tests/run.ps1 -Apk ./output/VolumeControl-2.7.1-redesign20-icons-settings-api18.apk
./source/tests/run-icons-android.ps1 -BuildOnly
./source/tests/run-icons-android.ps1 -Serial emulator-5600 -ExpectedAvd VolumeIcons_API18
```

Последняя команда предназначена только для отдельного одноразового эмулятора API18/mdpi; меняет настройки тестового приложения, запускает реальные точки входа и возвращает иконку №7 после UI-прогона. Обычный телефон или магнитолу автоматически не выбирает. AVD нужно создать и запустить заранее. Команда не создаёт эмулятор.

| Проверка | Уровень и ограничение |
|---|---|
| IconSelectionTest | 16 переходов, сохранение, восстановление, сбой каждого изменения компонента, ошибка записи, восстановление после прерывания; модель с подставным backend |
| check_launcher_icons.py | Четыре SVG-экспорта в шести плотностях; независимый hash baseline; прозрачность, размеры, различимость файлов, №7 по умолчанию; четыре alias и одна включённая точка входа; реальные ресурсы и DEX APK |
| LauncherIconTest | Реальный PackageManager под instrumentation целевого приложения: 16 переходов, единственный разрешаемый пункт меню, название, loadIcon не меньше512px и точная графика против512px baseline, запуск через каждый alias |
| LauncherIconUiTest | Отсутствие верхней кнопки «Иконка», достижимость «Работа приложения» через горизонтальную ленту, четыре открытых варианта, реальные нажатия, выделение выбора, размер и горизонтальная доступность кнопок, сохранение после force-stop, снимки каждого состояния |

Проверка bitmap в PackageManager подтверждает графику разрешённой точки входа. Она не подтверждает кеш конкретного стороннего лаунчера. Снимки UI требуют отдельного визуального ревью; наличие автотеста и его компиляция не означают успешный runtime-прогон.

Графические эталоны находятся в `icon-baselines/`; генератор ресурсов их не перезаписывает. Их обновление — отдельное осознанное действие после проверки нового дизайна. №07 в redesign19 использует детальный растровый мастер1254px, №06/08/10 — SVG. Лаунчер получает отдельные512px nodpi изображения и уменьшает их для своих значков.

В этой среде ADB завершился до соединения: `failed to create fdevent interrupt socketpair: Invalid argument`. Поэтому instrumentation/UI runtime, меню стороннего лаунчера и скриншоты приложения пока **NOT RUN**, а не PASS.

Из корня проекта:

```powershell
./source/tests/run.ps1
```

Команда компилирует производственные Java-классы, запускает четыре набора проверок без Android и тест прозрачности с подставными контрактами Android окон. Ошибка любого набора останавливает запуск.

Для дополнительной проверки собранного redesign17:

```powershell
./source/tests/run.ps1 -Apk ./output/VolumeControl-2.7.1-redesign17-dual-autohide-api18.apk
```

| Набор | Что проверяет |
|---|---|
| DualScaleStateTest | Разрешённые стороны, общий уровень, единственный владелец жеста, чужой палец, совместная/раздельная видимость, смена режима, сон/пробуждение и запоздалые таймеры модели |
| ScalePlacementTest | Все 16 старых индексов, три новых положения, неизвестные значения и доступность совместного режима |
| VolumeConfirmationTest | ACK, повторные подтверждения, быстрые команды, устаревшие значения и граница 350 мс |
| AutoHideRegressionTest | Все 20 комбинаций задержки и затухания, границы времени, удержание и отпускание, повторное появление, старые callbacks, закрытие и независимые таймеры |
| TouchGuardStateTest | Короткое касание не меняет громкость, подтверждённое удержание разрешает изменение, движение до подтверждения отменяет жест; детерминированная модель, без реального Android touch |
| check_overlay_visibility.py | Производственный OverlayVisibility: отдельное окно левой шкалы/процентов, дочерняя правая шкала, скрытие и появление, сохранение положения, границы alpha и сброс прежней View alpha |
| check_dual_scale_apk.py, validate_apk.py | При переданном APK: DEX-интеграция, 19 положений, ресурсы, версия, API18, подпись обновления и целостность |

Используются JDK и Python из текущего локального toolchain; пути заданы в run.ps1 и Python-проверках. Для APK-проверок нужны локальные зависимости анализа и прежний APK, указанные в validate_apk.py. Это не автономная CI-конфигурация для чистого checkout.

Тесты моделей и подставных окон не проверяют Android-композитор, реальный мультитач, мультируль и аудио магнитолы. Сценарии эмулятора и их фактические результаты описаны отдельно в docs/RELEASE-redesign17.md. APK эти команды не устанавливают и не пересобирают.
