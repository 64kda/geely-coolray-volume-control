# Регулятор громкости: оформление для Coolray

Дата: 03.11.2026. Этот документ описывает первоначальный этап дизайна. Затем владелец выбрал вариант 3 и запросил пересборку. Текущий результат и проверки находятся в `../output/ПЕРЕСБОРКА.md`; первоначальные ограничения ниже относятся к состоянию до внедрения.

## Задача и границы этапа

Требования владельца: новая иконка, полная русификация настроек, меню в стиле существующего мультимедийного виджета Coolray / Spotify без удаления настроек, современная шкала громкости, обязательная совместимость с Android 4.3. Дополнительно применены `/ub-mode` и TokenEconomizer. Генератор изображений дважды завершился ошибкой соединения; пользователь явно выбрал векторную иконку и точные макеты без генератора.

Подготовлены три независимых направления одного интерфейса. Это статические макеты, а не работающий Android-интерфейс. Все используют одну палитру и сохраняют одинаковый перечень функций. Выбор касается организации меню и подачи шкалы.

## Русификация

Готовы `localization/res/values-ru/strings.xml` и `arrays.xml`, а также русские базовые копии в `values`: 91 строка и 4 массива с 30 пунктами. Имена, число и порядок вариантов сохранены. Таблицы для проверки перевода: `strings-review.csv`, `arrays-review.csv`. Включены доступные строки библиотечных диалогов. Бренды и URL не переводились.

Значимые уточнения: «Прозрачность» заменена на «Непрозрачность», потому что растёт alpha; `ShowNotification` описан как системная панель громкости; `DTMF` → «Тоновый набор»; исправлено «мультимедия» → «мультимедиа»; длина и толщина различаются; все 16 привязок названы явно.

Русские базовые копии дают русскую резервную локаль. При внедрении нужно согласованно обработать существующие переводы других локалей: они могут перекрывать базовые строки при другом языке системы. На этом этапе ресурсы APK не изменены. Системные окна Android, страницы в браузере и загружаемая реклама управляются внешними компонентами; их язык приложение гарантировать не может.

Нужен отдельный проход по строкам в коде: `%d%%`, частоты `Hz` и усиление `dB`, закрывающий `X`, описания доступности. В новой версии выводить частоты как «Гц», усиление как «дБ» и описание кнопки «Закрыть». Форматы, числовые значения, ключи сохранения и идентификаторы каналов не переводить. Это ещё не выполненная замена в APK.

## Проект шкалы

Базовое оформление — контрастная заполненная дорожка с белым бегунком, округлыми краями и одним акцентным цветом. Положение, длина, толщина, два исходных вида и пользовательские цвета остаются настройками. При выборе «Столбики уровня» сохранить ступенчатый рисунок, используя новую палитру и скругления; не подменять этот режим сплошной полосой. Текущий лист показывает сплошной режим в трёх компоновках, а не полный набор вариантов и состояний.

| Параметр | Проектное правило |
|---|---|
| Направление | Горизонталь: минимум слева; вертикаль: минимум снизу; существующая инверсия по привязке сохраняется |
| Шаг | Фактические дискретные уровни выбранного AudioManager-канала; проценты — только отображение |
| Касание | Область не менее 48 dp поперёк шкалы, даже при более тонкой видимой полосе; у края границы подрезаются экраном |
| Выбранный канал | Доступен с главного экрана; имя присутствует в доступном описании шкалы |
| Обычное состояние | Графитовый фон, сохранённое пользовательское заполнение, белый бегунок |
| Касание / фокус | Заметный контур или увеличение бегунка без изменения уровня до допустимого жеста |
| Ноль / максимум | Бегунок остаётся видимым; значение совпадает с реальным уровнем; нет обязательного переключения режима звонка |
| Автоскрытие | Невидимая область не должна перехватывать обычные касания; способ повторного открытия требует проверки на магнитоле |
| Недоступный канал / эффект | Понятное объяснение; интерфейс не показывает ложный успех |
| Движение | Минимальная либо отключаемая анимация; без размытия, теней и непрерывного перерисовывания в покое |

Не менять звук при входе в настройки, отрисовке предпросмотра или смене цвета. Режим «Все каналы» остаётся явным выбором пользователя. Существующие действия при нулевом уровне сохраняются, автоматическое новое действие не добавляется. Жесты должны учитывать ACTION_CANCEL, системный перехват и несколько пальцев. Масштабирование и смена ориентации не должны уносить шкалу за экран.

## Обязательный контракт Android 4.3

Android 4.3 — API18: [список платформ Android](https://developer.android.com/tools/releases/platforms). Совместимость означает установку и реальную работу, а не только `minSdkVersion` в манифесте.

1. Для базовой версии использовать возможности API18: View, Canvas, Paint, Path, GradientDrawable, StateListDrawable и доступный Switch. Не требовать Compose, Material Components, штатный VectorDrawable, elevation, ripple или RenderEffect. Более новые вызовы возможны только в изолированных ветках с проверкой версии и полноценным старым путём.
2. Не повышать `minSdkVersion` выше 18. Точные min/target для изменённого APK определить при восстановлении сборки. Смена target сама по себе не нужна для редизайна. Обычная новая установка на Android 14+ — отдельная задача, не условие этой версии для магнитолы.
3. Сохранить доступный на API18 механизм overlay и аудиоканалы. Современный тип окна нельзя безусловно использовать на Android 4.3. При поддержке новых систем выбирать путь по версии.
4. APK должен иметь совместимую v1-подпись и пройти проверку с минимальной версией 18; более новые подписи могут присутствовать дополнительно. [Правила подписи Android](https://source.android.com/docs/security/features/apksigning), [apksigner](https://developer.android.com/tools/apksigner).
5. Launcher-иконка — PNG нужной плотности; графика шкалы — лёгкая Canvas-отрисовка, а не большой постоянно перерисовываемый bitmap. Не добавлять нативных библиотек без необходимости.
6. При другом ключе нельзя обещать обновление поверх оригинального APK. Ключ издателя не извлекается из APK. Для тестов нужен отдельный пакет либо согласованный безопасный путь установки. Не удалять исходное приложение и его данные автоматически.
7. Приёмка: эмулятор API18 и сама магнитола. Отдельно проверить аппаратные кнопки, разные уровни каналов, ноль/максимум, автозапуск, скрытие, удержание, несколько пальцев, эффекты, перезапуск службы и сохранение после выключения устройства.

На этом этапе совместимость изменённого APK не подтверждена: APK не собирался и не запускался. Проверка ресурсной заготовки с Android18 не подтверждает работу звука или overlay.

## Последующие этапы

Выбрать один визуальный вариант. Затем восстановить воспроизводимую сборку из исходников, если они есть, либо отдельным этапом из APK с сохранением соответствия ресурсов и кода. Внедрить локализацию и оформление небольшими проверяемыми изменениями. После сборки провести статическую проверку и тесты API18, затем проверить устройство. Гарантия «всё работает на Android 4.3» до этих проверок не даётся.

Существующие настройки и значения сохранения должны мигрировать без `clear()` общего хранилища. Нельзя вручную подставлять новый `resources.arsc` из изолированного теста: числовые resource ID должны оставаться согласованными с Dalvik-кодом.
