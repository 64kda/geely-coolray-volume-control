## Исправление самопроизвольной громкости в настройках — 03.11.2026

Пользователь сообщил об уменьшении мультимедиа при переходе между вкладками и применении настроек. Подтверждённая цепочка в коде: повторное событие выбора Spinner → StartService → Initialize → SetVolume с текущим значением музыки, затем ReadEqMixState → восстановление семи сохранённых уровней каналов. Это могло переигрывать старые значения микшера или менять выбранный канал. Реальный stack/log устройства не получен.

Initialize теперь вызывает ScaleState.sync: только считывание max/current выбранного канала и установка состояния View. Авто/все каналы отображаются через общий pure resolver VolumeMath.displayStream, согласованный с главным экраном. Из ReadEqMixState исключено восстановление уровней микшера; загрузка полос, басов и стереоэффекта оставлена. Исходные ручные SetVolume/SetStreamVolume/onValueChanged и системный VolumeChangeReceiver сохранены. Программный setProgress передаёт fromUser=false, исходный onValueChanged в этом случае не меняет аудио.

Перед перестройкой главной формы четыре Spinner получают фильтр повторного текущего выбора. Поэтому перенос между страницами не вызывает ложного сохранения/перезапуска. Настоящий выбор нового пункта делегируется исходному обработчику.

## Автоскрытие маркера — 03.11.2026

Фактический владелец компонента — отдельный «Регулятор громкости», пакет rubberbigpepper.VolumeControl.redesign. Название BluetoothWidget в приложенном задании не совпадает с владельцем найденного белого маркера. Проект виджета не изменялся. В этой папке прежде не было PROJECT_STATUS.md и CHANGELOG.md; применены инструкции AGENTS.md из чата и ub-mode.

Причина: ScaleRenderer.draw безусловно вызывал drawCircle в вертикальной ветке. Маркер не был отдельным View. Уровень поступает через ZoomView.setProgress, включая существующий VolumeChangeReceiver. Управление штатной аудиосистемой не перерабатывалось.

Решение: состояние MarkerVisibility с инъекцией часов и планировщика; View-адаптер MarkerController; событие только внутри ветки фактического изменения mProgress. Отложенный callback проверяет актуальный срок и состояние компонента. При detach callback отменяется, при attach создаётся новый контроллер. Установка начального уровня в Initialize завершается сбросом в IDLE. Автоскрытие явно включено только для m_cZoomView плавающей шкалы; в renderer условие изменено только для вертикального круга. Без новых зависимостей, API выше 18 и фонового polling.
