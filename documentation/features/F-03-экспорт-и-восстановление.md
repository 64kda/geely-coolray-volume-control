# F-03. Экспорт и восстановление настроек

Дата: 11.11.2026. Статус: ТЗ, к реализации. Общие правила: [README](README.md).

## Цель и объём

Сохранять оформление и поведение регулятора в переносимый файл и восстанавливать их после обновления/переустановки. Восстановление не должно неожиданно менять текущий звук или автоматически запускать остановленную шкалу.

Первый этап включает настройки шкалы, её поведения и пользовательские параметры управления. Текущие уровни каналов, настройка эквалайзера, басов и виртуализатора не входят. В интерфейсе это указать: «Сохраняются оформление и поведение. Громкость и звуковые эффекты не входят в копию». Это резервная копия настроек регулятора, не полный бэкап данных приложения.

## Интерфейс и файлы

Во вкладке «Работа приложения» добавить раздел «Резервная копия» с кнопками «Экспортировать настройки» и «Восстановить из файла».

Экспорт: предложить имя `VolumeControl-settings-YYYYMMDD-HHmmss.json` по локальному времени устройства и выбрать каталог. Запись в общедоступный каталог должна работать на API18: собственный простой выбор доступного каталога, с начальным Downloads, проверкой доступности и прав. Добавление только необходимого WRITE_EXTERNAL_STORAGE для API18 допускается; не добавлять сеть и доступ ко всему файловому дереву ради этой функции. На более новых API, если они уже поддерживаются приложением, разрешён адаптер системного выбора документа с проверкой версии; нельзя делать API19+ единственным путём. Требования этой задачи не расширяют заявленную совместимость приложения на новые Android.

Импорт: ACTION_GET_CONTENT с CATEGORY_OPENABLE, обработка content/file URI через ContentResolver. Если обработчика выбора файлов нет, собственный выбор JSON из доступного каталога. У собственного выбора есть переход к родителю и список каталогов/JSON; не показывать приватные каталоги других приложений. При недоступности хранилища объяснить причину и предложить другой путь. Отмена любого выбора ничего не меняет.

Экспортировать во временный соседний файл, закрыть поток, проверить данные и только затем присвоить конечное имя. Не перезаписывать существующий файл без явного согласия; при отказе предложить другое имя. При ошибке удалить только свой временный файл, исходные настройки и чужие файлы сохранять. Успех показывать после завершения записи, с реальным путём.

## Формат и перечень ключей

UTF-8 JSON, максимум 64 КиБ при чтении потока, до разбора. Обязательные верхние поля: `format="volumecontrol-settings"`, `schemaVersion=1`, `package="rubberbigpepper.VolumeControl.redesign"`, `appVersion` (строка), `exportedAt` (ISO8601 с часовым смещением), `settings` (объект). Версия приложения — справочная, совместимость определяется схемой и поддерживаемыми ключами. Никаких путей к приватным файлам, идентификаторов устройства, ключей подписи и двоичных вложений.

settings содержит только белый список. Имена совпадают с Common; типы сверяются строго, без преобразования строк в числа и чисел в boolean:

| Тип | Ключи |
|---|---|
| int ARGB, знаковый 32-битный | Main color, Background color, Active color, Inactive color |
| int | Size, Length, Gravity, Horizontal offset, Vertical offset, Bar type, Percent position, Stream type, Action on 0 volume |
| boolean | Fullscreen, Show notification, Sound notification, Enable EqMix, Start after reboot, Auto hide |
| int, если F-01 реализована | Auto hide delay ms, Auto hide fade ms |
| boolean/int, если F-02 реализована | Touch guard enabled / Touch guard hold ms |
| boolean, только в сборке без F-02 | Reaction delay |

Диапазоны: Size=0…90, Length=0…130, Bar type=0/1/2, Percent position=0/1, Action on 0 volume=0/1/2. Для Gravity и Stream type использовать именно допустимые сохраняемые значения текущих списков, не позиции UI. Диапазоны смещений и преобразование их единиц установить по действующему коду до реализации и включить в единый валидатор; нельзя угадать их по разрешению экрана. После расчёта геометрии на текущем экране шкала должна иметь доступную область касания. Если импортированное положение недоступно, до подтверждения предложить безопасное положение и явно показать корректировку; не менять её молча.

Параметры F-01/F-02 принимают только перечисленные в их ТЗ значения. Не экспортировать `Stream N level`, `Band N level`, Equalizer enabled, Bass level, Virtualizer level, Flat band defaults и неизвестные служебные ключи. Enable EqMix переносит только доступность интерфейса эффектов, не их состояние.

Экспорт записывает все поддерживаемые ключи списка с эффективными значениями, включая defaults. Импорт допускает отсутствие ключей: они оставляют текущие значения и перечисляются в предпросмотре как отсутствующие. Пустой settings отклонять. Неизвестные ключи, повторяющиеся имена JSON, неверные типы/диапазоны, чужой package/format, будущую schemaVersion отклонять целиком, с понятным сообщением. Не игнорировать неизвестную настройку молча. Для файла старой сборки с Reaction delay в сборке F-02 применить миграцию F-02; если присутствуют также новые ключи защиты, отклонить неоднозначный файл.

## Проверка, подтверждение и применение

1. Прочитать и полностью проверить файл без записи в Common, запуска службы и аудиокоманд. Имя/версию/дату считать только данными, не командами и не путями для записи.
2. Показать краткий список изменений по понятным названиям, пропущенные поля, корректировку положения и изменение автозапуска. Отдельно повторить, что громкость/эффекты не восстанавливаются. Если изменений нет, сообщить об этом без перезапуска службы.
3. До подтверждения не создавать изменений. Кнопки «Восстановить» и «Отмена». Повторно проверить, что настройки не изменились со времени предпросмотра; при изменении пересчитать предпросмотр и запросить новое подтверждение.
4. Сохранить предыдущие значения затрагиваемых ключей во внутреннюю восстанавливаемую копию до применения. Обновить все импортируемые значения одной транзакцией SharedPreferences.Editor с проверкой результата; не вызывать clear и не копировать Common.xml целиком. На ошибке не показывать успех. Обеспечить восстановление прежнего набора при следующем запуске, если сбой произошёл между сохранением recovery-копии и завершением операции; алгоритм и метку завершения проверить тестами с прерыванием.
5. При успешном сохранении обновить форму без ложных пользовательских событий и без записи звука. Для работающей шкалы применить новые параметры один раз через существующую read-only инициализацию; для отсутствующей шкалы не вызывать StartService только ради импорта. Изменение Start after reboot влияет на будущий запуск, но не запускает шкалу сейчас.
6. Если параметры сохранены, но применение окна завершилось ошибкой, явно сообщить «Настройки сохранены, применить шкалу не удалось» и дать «Вернуть предыдущие настройки». Не выдавать это за полный успех и не менять аудио ради восстановления. Разделять завершение записи и применение UI в recovery-протоколе.
7. Добавить действие «Вернуть настройки до последнего восстановления» с подтверждением. Хранить одну предыдущую копию в приватном каталоге; новый успешный импорт заменяет её. Откат меняет только ключи последнего импорта, восстанавливает отсутствие ключа, если его раньше не было, и не запускает остановленную шкалу. Переживает перезапуск; не включается в экспорт. Если после импорта затрагиваемые поля были вручную изменены, предупредить об их замене в предпросмотре отката.

Импорт — операция с пользовательскими данными. Реализацию схемы, валидации, recovery-протокола и порядка применения проверить независимым критиком до подключения записи/применения, в пределах бюджета AGENTS.md; финальная проверка при существенном остаточном риске. Подтверждение в UI относится к пользователю приложения, не требует дополнительного согласования каждого шага разработки в чате.

Хранилище назначения — `Context.getSharedPreferences("Common", MODE_PRIVATE)`. Под одной транзакцией выше понимается один Editor и один синхронный commit с проверкой boolean, а не apply и не гарантия атомарности нескольких файлов. Recovery-копия, Common и метка завершения не образуют общую транзакцию Android. До реализации описать порядок их надёжной записи и восстановления при прерывании между любыми двумя шагами; чтение recovery и завершение восстановления выполнять до загрузки параметров в службу/UI. Не считать commit=false доказательством отсутствия изменений в памяти: вернуть согласованное прежнее состояние через recovery, при неудаче прекратить дальнейшее применение и показать ошибку. Одновременные записи из формы на время применения блокировать, восстановление не должно перетирать незатронутые ключи.

## Проверки и приёмка

- Round-trip: все разрешённые эффективные значения экспортируются и восстанавливаются без потери типов, цветов, таймингов F-01 и защиты F-02. Проверить русские имена файлов, content URI и собственный API18 выбор каталогов.
- Повреждённый/обрезанный JSON, файл >64 КиБ, дубли ключей, огромные числа, дробные int, null, чужой пакет, будущая схема, неизвестный ключ, недоступное расположение: обработка по контракту, без частичной записи и аудиокоманд.
- Отсутствующие поля сохраняют текущие; миграция Reaction delay работает. Старые/неподдерживаемые новые ключи дают явный отказ, а не тихую потерю.
- Отмена выбора/предпросмотра, нет места, read-only каталог, ошибка чтения URI, неудачный commit и аварийное завершение на каждом этапе: исходные/восстановленные данные соответствуют recovery-протоколу. Нет ложного сообщения об успехе.
- Соседние ключи эффектов/микшера и неизвестные внутренние поля Common сохраняются. Сравнить уровни всех аудиоканалов и состояния эффектов до/после экспорта, импорта и отката: изменений нет.
- Импорт при показанной, автоскрытой и явно выключенной шкале; один refresh для работающей и отсутствие запуска для выключенной. Повторное открытие настроек не перезаписывает импорт устаревшими значениями формы.
- Откат после restart, повторного импорта, ручных изменений и отсутствие прежнего ключа. Подпись/пакет сохранены; переустановка с удалением данных уничтожает внутренний откат, внешний JSON остаётся доступен, если хранилище его сохранило.
- На API18 без внешнего файлового менеджера экспорт/импорт доступны через встроенный путь. На магнитоле подтвердить доступность USB/внутреннего хранилища, выбор файлов и восстановление положения на фактическом экране.

Результат: код, описание схемы и таблица валидаторов, тестовые корректные/ошибочные файлы, проверки с имитацией сбоев, новый API18 APK и отчёт. Облачную синхронизацию, ZIP-архивы приложения, перенос уровней звука/эффектов и автоматическое восстановление из произвольных файлов не включать.
